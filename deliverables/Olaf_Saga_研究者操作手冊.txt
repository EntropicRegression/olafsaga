1. 快速開始與系統範圍
一分鐘快速開始  登入正式站後，先按「更新」確認資料，再依序檢查總覽、學習場次與受試者。單筆帳號可直接在「受試者」建立，多筆帳號使用 CSV；下載資料使用右上角「匯出研究資料」。
1.1 研究者可執行的工作
* 查看受試者數量、進行中場次、完成率與音檔容量估算。
* 比較五個故事節點的通過率、Accuracy 與 Fluency。
* 查看 Agent 1／Agent 2 分派平衡與各類未通過原因。
* 依受試者、班級或場次搜尋，開啟逐輪逐字稿、分數與私人 WAV 音檔。
* 新增研究註記；註記與原始嘗試資料分開保存。
* 直接建立單一學生／受試者帳號，或以 CSV 批次匯入。
* 編輯判定門檻並發布不可變的新研究設定版本。
* 發布新的英文詞表版本，供之後建立的新場次使用。
* 建立 CSV、JSON 及（若背景工作已設定）WAV ZIP 匯出。
1.2 目前介面的限制
* 已發布的研究設定版本不可覆寫；若需調整，必須發布另一個新版本。
* 沒有受試者刪除按鈕，也沒有獨立的密碼重設流程。
* 私人音檔可播放，但目前介面沒有刪除音檔按鈕。
* 自動刪除目前為關閉；資料保留與刪除需依研究計畫另行執行。
2. 登入、登出與帳號安全
2.1 登入前準備
項目要求正式網址https://olafsaga.vercel.app登入身分研究者帳號由系統管理者提供的研究者代碼密碼研究者專用密碼；不得與學生或未授權人員共用建議環境桌上型或平板瀏覽器；穩定網路；避免公共電腦
2.2 登入步驟
1. 開啟正式網址：在瀏覽器網址列輸入 https://olafsaga.vercel.app。
2. 選擇研究者：在登入卡上切換至「研究者」。
3. 輸入帳號與密碼：確認沒有多餘空白，密碼大小寫須完全一致。
4. 進入系統：按「進入系統」，等待研究進度總覽顯示。
5. 確認雲端狀態：左側狀態應顯示 Cloud connected／Firebase · Azure。
網址提醒  若登入後只看到「正在整理研究資料...」，先檢查網址。舊部署網址可能仍能顯示登入頁，但後台 API 可能已失效；請回到正式固定網址重新登入。
2.3 登出與安全規範
* 工作完成後按左側「登出研究後台」，不要只關閉分頁。
* 下載檔案含逐字稿與研究資料，僅保存在核准的加密裝置或研究儲存空間。
* 不要把密碼寫入 CSV、報告、聊天紀錄或共同文件。受試者 CSV 的初始密碼欄位應由授權人員保管。
* 懷疑密碼外洩時，立即停止使用並請系統管理者重設。
3. 研究進度總覽
登入後預設進入「總覽」。右上角「更新」會重新讀取最新雲端資料；搜尋框可依研究代碼、班級或場次內容篩選最近學習場次。

3.2 分析區塊
* 五節點表現：逐節點查看嘗試數、通過率、平均 Accuracy 與 Fluency。
* 實驗組平衡：確認 Agent 1 與 Agent 2 的分派是否接近 1:1。
* 需要重試的原因：統計語言不明、文法難以理解、離題、過短、低準確度、低流暢度或低情緒表現等原因；不含技術錯誤。
* 資料完整性：顯示原始 WAV 保存、流程版本、個資最小化與自動刪除狀態。
* 最近學習場次：快速查看受試者、班級、組別、節點、狀態與最後更新時間。
解讀原則  總覽是監控與品質檢查工具，不應單獨作為學習成效結論。正式分析前仍應使用匯出資料，依研究設計進行清理、排除與統計。
4. 受試者帳號建立與 CSV 匯入
4.1 建立前必要條件
* 已由研究流程完成有效同意；系統本身不負責取得或驗證研究同意。
* 每位受試者有唯一研究代碼，不在代碼中放姓名、學號、電話或 Email。
* 已決定班級代碼、同意書版本與同意時間。
* 單筆建立的初始密碼至少 8 個字元，並須包含英文字母與數字；CSV 密碼另須避免逗號。
4.2 直接建立單一學生帳號
1. 開啟受試者頁：從左側選單按「受試者」。
2. 輸入學生代碼：使用 3-40 字元的英文字母、數字及連字號；系統會自動轉成大寫。
3. 設定初始密碼：自行輸入，或按「產生安全密碼」。可使用顯示與複製按鈕核對，但只應透過安全管道交付。
4. 輸入班級代碼、同意書版本與取得研究同意時間。
5. 按「建立帳號」：成功後名單會重新載入，學生可立即從學生入口登入。
6. 抽樣驗證：確認「已建立帳號」中的代碼與班級正確。
重複帳號保護  單筆建立會同時檢查 Firebase Authentication 與 Firestore。若代碼已存在，系統會拒絕建立，不會覆寫既有密碼、分組或研究紀錄。
訪客預覽模式  可操作表單與檢查版面，但不會建立正式帳號。

4.3 CSV 欄位規格
欄位格式與限制範例code3-40 字元；建議只用英文字母、數字與連字號；必須唯一STUDENT-001password8-128 字元；不得含逗號；大小寫敏感ChangeMe123!classId1-80 字元的班級或群組代碼CLASS-AconsentVersion1-80 字元的同意書版本consent-2026-v1consentedAt完整 ISO 8601 日期時間，必須包含時間與時區2026-08-26T00:00:00.000Z
code,password,classId,consentVersion,consentedAt

重要  系統目前以逗號直接拆分 CSV，不支援儲存格內逗號或複雜引號規則。每次最多匯入 200 筆。請以 UTF-8 CSV 儲存。
4.4 CSV 批次匯入步驟
1. 開啟受試者頁：從左側選單按「受試者」。
2. 最後檢查 CSV：確認標題列完全一致、沒有空白列、日期為完整 ISO 時間。
3. 選擇檔案：在「批次匯入受試者」按「選擇 CSV」，上傳準備好的檔案。
4. 確認結果：頁面會顯示成功筆數並重新載入名單。
5. 抽樣驗證：在「已建立帳號」確認代碼與班級；以一個測試帳號從學生入口登入。
6. 安全交付：將每位學生的代碼與初始密碼個別、安全地交付，避免整份名單公開傳送。
避免重複匯入  目前重複匯入相同 code 會重設密碼、解除停用，並把 group 設回未分派。對已開始研究的學生，這可能破壞固定分組。請只匯入新代碼；若需重設個別密碼，交由系統管理者處理。
5. 學習場次、逐輪紀錄、音檔與研究註記
5.1 尋找與開啟場次
* 在「總覽」或「學習場次」使用搜尋框輸入受試者代碼、班級或其他場次文字。
* 場次表顯示受試者、班級、實驗組、目前節點、狀態及更新時間。
* 按最右側箭頭開啟 SESSION DETAIL；按右上角 X 或抽屜外側關閉。

5.3 播放私人 WAV
有音檔路徑的嘗試會顯示「播放私密 WAV」。按下後系統建立五分鐘有效的播放連結並留下稽核紀錄。連結到期後，重新按播放即可取得新連結。
* 只在不會被旁人聽見的環境播放。
* 不要複製或轉傳短效連結；連結雖會到期，仍屬研究資料。
* 若播放沒有聲音，確認裝置音量、瀏覽器自動播放限制及網路連線。
5.4 新增研究註記
12. 開啟場次明細：捲動至「研究者註記」。
13. 輸入客觀觀察：最多 2,000 字；避免輸入可直接辨識個人的資料。
14. 保存註記：按「保存註記」。註記會附上研究者與時間，且不覆寫原始嘗試。
6. 研究設定與詞表版本
6.1 可編輯的判定門檻
門檻目前值用途每輪最低英文詞數8過短判定Accuracy60發音準確度最低值Fluency60口語流暢度最低值emotion2vec 信心值0.30需要情緒判定時使用每輪有效嘗試上限3第三次仍未達標時輔助前進錄音秒數上限30到時自動停止
介面另可設定「目標情緒排名」，預設為前 2 名。所有欄位都有安全範圍：最低英文詞數 1-50、Accuracy／Fluency 0-100、情緒信心值 0-1、目標情緒排名 1-10、有效嘗試上限 1-10、錄音上限 5-120 秒。

6.2 編輯並發布研究設定
1. 從左側選單開啟「研究設定」。
2. 確認「目前版本」及各門檻值；未修改時「發布新版本」按鈕會停用。
3. 修改需要調整的欄位。若要放棄尚未發布的修改，按「還原」。
4. 在「變更原因」輸入至少 5 個字，說明依據與目的，最多 300 字。
5. 按「發布新版本」。系統會建立新的不可變版本，並將門檻、變更原因、研究者與時間寫入稽核紀錄。
6. 確認成功訊息與新版本代碼；必要時使用測試學生建立新場次驗證流程。
版本套用規則  只有之後新建立的場次會鎖定最新版本；已開始的場次繼續使用原門檻。錄音上限會同時套用於學生端自動停止與後端 API 檢查。
訪客預覽模式  可調整欄位並檢查按鈕狀態，但不會發布至 Firestore。

6.3 發布英文詞表
* 準備 CSV 或 TXT；單字可用換行、逗號、分號、Tab 或空白分隔。
* 檔案需含 100-5,000 個有效項目；系統會移除重複項與常見標題 word／words／vocabulary。
* 在「研究設定」的「英文詞表」卡片按「匯入並發布新詞表」。
* 系統自動建立不可變版本並顯示有效單字數。
* 只有之後新建立的場次會鎖定新詞表；已開始的場次維持原版本。
發布前檢查  先在研究團隊外部檔案完成審核。發布後不覆寫舊版本；若內容有誤，應修正檔案後再發布另一個新版本。
7. 研究資料匯出
7.1 建立匯出
15. 更新資料：先按「更新」，確認總覽反映最新場次。
16. 建立匯出：按右上角「匯出研究資料」。
17. 下載 CSV／JSON：系統顯示下載連結；連結五分鐘內有效。
18. 查詢 WAV ZIP：若狀態為 queued，稍後按「查詢 WAV ZIP」；完成後立即下載。
19. 確認與歸檔：核對檔案大小、匯出時間與研究批次，移至核准儲存位置。

敏感資料  匯出檔可能包含聲音與逐字稿。下載、傳輸、備份、分析與刪除都必須遵循研究同意、IRB／倫理審查及機構資料管理規範。
8. 每日操作流程與資料治理
8.1 實驗開始前
* 確認受試者已完成研究同意，且單筆表單或 CSV 的 consentVersion／consentedAt 正確。
* 確認受試者代碼唯一、初始密碼可用，且學生從正式網址登入。
* 按「更新」確認雲端連線與服務狀態。
* 抽查一個測試帳號的麥克風、錄音、逐字稿及場次資料。
* 確認研究設定版本與詞表版本皆符合本次研究批次。
8.2 實驗進行中
* 監看進行中場次及最後更新時間，但不要在學生錄音時重設或重匯入其帳號。
* 技術錯誤不列入有效嘗試；若連續技術錯誤，先處理網路、麥克風或雲端服務。
* 研究註記使用客觀描述，不修改或覆寫原始逐字稿與評分。
8.3 實驗結束後
* 確認應完成的場次狀態為 completed，並處理長時間停留在 active 的案例。
* 按研究批次匯出 CSV／JSON；如需要，等待 WAV ZIP 完成。
* 把匯出檔移至核准的研究儲存位置，記錄版本與雜湊或檔案大小。
* 登出研究後台，移除下載資料的非必要副本。
8.4 資料治理重點
稽核補充  單筆建立學生帳號與研究設定發布都會留下研究者、時間、版本及必要操作資訊；稽核紀錄不保存學生明文密碼。

9. 常見問題與故障排除
新增功能排除方式：
* 建立帳號顯示「代碼已存在」：Authentication 或 Firestore 已有相同代碼。請改用新研究代碼，不要以 CSV 重匯入來繞過保護。
* 「發布新版本」無法按：先修改至少一項門檻，並輸入至少 5 個字的變更原因；確認數值位於畫面允許範圍。
* 設定發布成功但學生仍使用舊值：已開始的場次會鎖定原版本，屬正常行為；請使用尚未開始的新測試帳號驗證新版本。
* 儲存時出現 Firestore undefined 錯誤：重新整理後重試；若仍發生，記錄受試者代碼、時間與操作步驟交給系統管理者，請勿重複送出多次。
